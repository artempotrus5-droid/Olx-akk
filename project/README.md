# OLX Accounts Bot

Внутренний Telegram-бот для распределения корпоративных OLX-аккаунтов между сотрудниками.

## Возможности

- ➕ Добавить аккаунт (пошагово: email → пароль → год и описание)
- 📋 Взять аккаунт (список свободных/занятых, атомарная выдача)
- 🔄 Вернуть аккаунт (только свои)
- 🗑 Удалить аккаунт (с подтверждением)
- 📖 История аккаунтов — общая для всех, открывается как Telegram Mini App

## Хранение данных

По умолчанию бот использует обычный файл SQLite. На бесплатном тарифе Render
файловая система контейнера эфемерная — при каждом передеплое или
"пробуждении" после сна файл базы может быть стёрт.

Чтобы данные (аккаунты и история) не терялись, подключите бесплатную базу
**Turso** — см. раздел ниже. Это займёт 5 минут и бесплатно.

### Хранение данных без потерь (Turso)

1. Установите Turso CLI на своём компьютере:
   ```bash
   curl -sSfL https://get.tur.so/install.sh | bash
   ```
2. Войдите (откроется браузер, вход через GitHub):
   ```bash
   turso auth login
   ```
3. Создайте базу данных:
   ```bash
   turso db create olx-accounts-bot
   ```
4. Получите URL базы:
   ```bash
   turso db show olx-accounts-bot --url
   ```
   Скопируйте значение — это `TURSO_DATABASE_URL` (вида `libsql://olx-accounts-bot-ВАШ_АККАУНТ.turso.io`).
5. Создайте токен доступа:
   ```bash
   turso db tokens create olx-accounts-bot
   ```
   Скопируйте полученную строку — это `TURSO_AUTH_TOKEN`.
6. На Render, в настройках сервиса → Environment, добавьте эти две
   переменные (`TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`) и сохраните.
   Сервис передеплоится и начнёт писать все изменения сразу в облако —
   теперь данные переживут любой передеплой и пересоздание контейнера.

Если переменные `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` не заданы, бот
просто продолжит работать на локальном SQLite-файле, как раньше — ничего
ломать не нужно, подключение Turso полностью опционально.

## Быстрый запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env   # заполните BOT_TOKEN (и, по желанию, Turso-переменные)
export $(cat .env | xargs)
python main.py
```

Бот и HTTP-сервер (health-check + Mini App) запускаются одной командой в одном процессе.

## Деплой на Render

1. Создайте бота через **@BotFather** в Telegram, получите `BOT_TOKEN`.
2. Загрузите этот проект в GitHub-репозиторий.
3. На [render.com](https://render.com) создайте **New → Web Service**, подключите репозиторий (Render автоматически найдёт `render.yaml` и `Dockerfile`).
4. В настройках сервиса укажите переменную окружения `BOT_TOKEN` (значение токена). По желанию — также `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` (см. раздел выше про Turso).
5. Запустите деплой. После первого успешного деплоя скопируйте выданный Render URL (например `https://olx-accounts-bot.onrender.com`) и добавьте его как переменную окружения `WEBAPP_URL`, затем передеплойте — кнопка «📖 История аккаунтов» откроется как Mini App.
6. Проверить работоспособность: `https://<ваш-домен>/health` → `{"status":"ok"}`.

## Переменные окружения

| Переменная           | Обязательна | Описание                                                        |
|-----------------------|:-----------:|------------------------------------------------------------------|
| `BOT_TOKEN`           | да          | Токен бота от BotFather                                           |
| `WEBAPP_URL`          | нет         | https-адрес сервиса, для кнопки истории (Mini App)                |
| `PORT`                | нет         | Порт HTTP-сервера (Render подставляет сам)                        |
| `DB_PATH`             | нет         | Путь к локальному файлу базы (кэш, по умолчанию `data/accounts.db`) |
| `TURSO_DATABASE_URL`  | нет         | URL облачной базы Turso — включает надёжное хранение данных       |
| `TURSO_AUTH_TOKEN`    | нет         | Токен доступа к базе Turso                                        |

```
│   └── formatting.py   — форматирование таблиц и истории

│   └── db.py           — работа с БД (SQLite или Turso, атомарные операции)
├── web/
│   ├── app.py            — FastAPI: /health, /api/history, Mini App
│   └── static/index.html — страница истории (Telegram Mini App)

├── requirements.txt
├── Dockerfile
├── render.yaml
└── .env.example
```
